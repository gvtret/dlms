refactor(cosem)!: drop duplicate PRIME PLC MAC address setup IC 84

IEC 62056-6-2 ED4 (2021) §4.12.10 and DLMS UA Blue Book Ed.
12.1 §4.12.10 both place the PRIME NB OFDM PLC MAC address
setup IC at class_id = 43, not 84. We already ship a built-in
`CosemMacAddressSetupObject` registered under class_id 43 with
exactly the same semantics, so the separate
`CosemPrimePlcMacAddressSetupObject` (class_id 84) was a
duplicate that additionally carried the wrong class_id on the
wire and would not interoperate with a spec-conformant peer.

Drop `CosemPrimePlcMacAddressSetupObject` (header, cpp impl,
unit tests). Use `CosemMacAddressSetupObject` for both
classical and PRIME PLC MAC address setup deployments.

Refresh COSEM IC support matrix (row 84 now reserved/
application-provided pointing back at row 43), COSEM API
guide and COSEM test plan accordingly.

Tests: dlms_cosem_tests 273/273 (-4 from the removed object),
full ctest 934/934.

BREAKING CHANGE: `dlms::cosem::CosemPrimePlcMacAddressSetupObject`
is removed. Migrate to `dlms::cosem::CosemMacAddressSetupObject`
(class_id 43), which already exposes the same `mac_address`
attribute with the spec-conformant class_id.
