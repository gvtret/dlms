fix(cosem)!: add list_of_allowed_callers (attr 7) to IC 28 Auto Answer

IEC 62056-6-2 ED4 (2021) §4.7.5 and DLMS UA Blue Book Ed. 12.1
§4.6.4 define the Auto Answer IC (class_id 28, version 0) with
seven attributes, the seventh being `list_of_allowed_callers`
(an `array of allowed_caller_element` enumerating caller
identifications the meter accepts). The built-in
`CosemAutoAnswerObject` stopped at attribute 6 and reported
`AttributeNotFound` for the spec-defined attribute 7.

Wire the missing attribute through the constructor, ctor
initializer list, access-rights table, read switch, write switch,
and add a `ListOfAllowedCallers()` accessor. The new attribute
joins the writable set governed by the caller-selected
`AttributeAccessMode`. Methods stay absent — the IC defines none —
so `InvokeMethod` still returns `MethodNotFound` for every id.

Expand the IC 28 tests: round-trip attribute 7 in
`ExposesAllAttributes`, extend the writable id set to
`{2, 3, 5, 6, 7}` in `MutableAttributesHonorAccessMode`, thread
the new payload through `NormalizesVersionAboveMax`, and shift
the `AttributeNotFound` probe from id 7 → 8.

Refresh the IC support matrix, COSEM API guide and COSEM test
plan to document attribute 7 and the new mutable set.

Tests: dlms_cosem_tests 275/275, full ctest 936/936.

BREAKING CHANGE: `CosemAutoAnswerObject` constructors now take an
extra `listOfAllowedCallers` content buffer (positioned after
`numberOfRings`). Callers must pass an encoded
`array of allowed_caller_element` payload (an empty `array(0)` is
a valid default) and update any code that previously
short-circuited at attribute 6.
