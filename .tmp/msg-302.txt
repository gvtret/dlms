fix(cosem)!: rebuild IC 67 Sensor Manager for ED4 layout

IEC 62056-6-2 ED4 (2021) §4.5.11 (and the DLMS UA Blue Book
Ed. 12.1 §4.5.11.2) defines the Sensor manager IC as class_id 67,
version 0 with fifteen attributes:
  1 logical_name, 2 serial_number, 3 metrological_identification,
  4 output_type, 5 adjustment_method, 6 sealing_method,
  7 raw_value, 8 scaler_unit, 9 status, 10 capture_time,
  11 raw_value_thresholds, 12 raw_value_actions,
  13 processed_value, 14 processed_value_thresholds,
  15 processed_value_actions
and one optional specific method: 1 reset(data).

The built-in object exposed an ad-hoc eleven-attribute layout
with vendor-style names (`status` at id 2, `serial_number` at
id 3, `device_type`, `manufacturer_id`, `firmware_version`,
`metrology_firmware_version`, `driver`, `communication_desc`,
`setup_desc`, `measurement_desc`) that did not match any DLMS
edition, and declared no specific methods.

- Replace the field set with the fifteen ED4 attributes in spec
  order.
- Constructor signature reworked to take the fourteen mutable
  payload buffers in spec attribute order followed by the
  shared AttributeAccessMode (and the optional version).
- Method 1 `reset(data)` surfaces as UnsupportedFeature (the
  built-in object does not own the sensor lifecycle); other
  method ids stay MethodNotFound.
- Rename C++ accessors to match the spec attribute names
  (SerialNumber, MetrologicalIdentification, OutputType,
  AdjustmentMethod, SealingMethod, RawValue, ScalerUnit,
  Status, CaptureTime, RawValueThresholds, RawValueActions,
  ProcessedValue, ProcessedValueThresholds,
  ProcessedValueActions); remove the old DeviceType /
  ManufacturerId / FirmwareVersion / MetrologyFirmwareVersion /
  Driver / CommunicationDesc / SetupDesc / MeasurementDesc
  accessors.
- Tests rewritten: ExposesAllAttributes / MutableAttributesHonor
  AccessMode now walk attrs 2..15; new
  ResetMethodIsUnsupportedFeature guards the optional method.
- Docs refreshed: IC support matrix, COSEM API guide and COSEM
  test plan describe the ED4 layout.

Tests: dlms_cosem_tests 277/277, full ctest 938/938.

BREAKING CHANGE: CosemSensorManagerObject constructors now take
the fourteen mutable buffers (serial_number,
metrological_identification, output_type, adjustment_method,
sealing_method, raw_value, scaler_unit, status, capture_time,
raw_value_thresholds, raw_value_actions, processed_value,
processed_value_thresholds, processed_value_actions) in spec
attribute order. The old constructor parameter set
(status, serial_number, device_type, manufacturer_id,
firmware_version, metrology_firmware_version, driver,
communication_desc, setup_desc, measurement_desc) is gone, and
the corresponding accessors (DeviceType, ManufacturerId,
FirmwareVersion, MetrologyFirmwareVersion, Driver,
CommunicationDesc, SetupDesc, MeasurementDesc) were removed.
Attribute ids and method id changed to match the spec
(serial_number is now id 2, status moved from id 2 to id 9,
optional method `reset` at id 1).
