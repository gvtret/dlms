fix(cosem)!: correct PRIME PLC MAC counters class_id 82->84

IEC 62056-6-2 ED4 (2021) §4.12.8 and DLMS UA Blue Book Ed.
12.1 §4.12.8 both define "PRIME NB OFDM PLC MAC counters"
with class_id = 84, not 82. Class_id 82 is reserved for the
unrelated "PRIME NB OFDM PLC MAC setup" IC (already
corrected in 0.87.0).

Our built-in `CosemPrimePlcMacCountersObject` carried the
correct attribute layout but reported the wrong class_id on
the wire, which would not interoperate with a spec-conformant
client/server.

Change `kPrimePlcMacCountersClassId` from 82 to 84, refresh
the unit-test class_id check, the COSEM IC support matrix
and the COSEM API guide.

Tests: dlms_cosem_tests 277/277, full ctest 938/938.

BREAKING CHANGE: `CosemPrimePlcMacCountersObject` instances
now report class_id `84` instead of `82` in their descriptor
and on the wire. Clients/servers that previously
interoperated with the incorrect class_id `82` will need to
be updated to the spec-conformant id `84`.
