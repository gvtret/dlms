fix(cosem)!: correct PRIME PLC Application Identification class_id 85->86

IEC 62056-6-2 ED4 (2021) §4.12.11 and DLMS UA Blue Book Ed.
12.1 §4.12.11 both define "PRIME NB OFDM PLC Application
identification" with class_id = 86, not 85. Class_id 85 is
reserved for the unrelated "PRIME NB OFDM PLC MAC network
administration data" IC (already corrected in 0.90.0).

Our built-in `CosemPrimePlcApplicationIdentificationObject`
carried the correct attribute layout but reported the wrong
class_id on the wire, which would not interoperate with a
spec-conformant client/server.

Change `kPrimePlcApplicationIdentificationClassId` from 85 to
86, refresh the unit-test class_id check, the COSEM IC
support matrix and the COSEM API guide.

Tests: dlms_cosem_tests 273/273, full ctest 934/934.

BREAKING CHANGE: `CosemPrimePlcApplicationIdentificationObject`
instances now report class_id `86` instead of `85` in their
descriptor and on the wire. Clients/servers that previously
interoperated with the incorrect class_id `85` will need to
be updated to the spec-conformant id `86`.
