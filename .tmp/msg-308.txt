fix(cosem)!: correct PRIME PLC MAC network stats class_id 83->85

IEC 62056-6-2 ED4 (2021) §4.12.9 and DLMS UA Blue Book Ed.
12.1 §4.12.9 both define "PRIME NB OFDM PLC MAC network
administration data" with class_id = 85, not 83. Class_id 83
is reserved for the unrelated "PRIME NB OFDM PLC MAC
functional parameters" IC (already corrected in 0.88.0).

Our built-in `CosemPrimePlcMacNetworkStatisticsObject`
carried the correct attribute layout but reported the wrong
class_id on the wire, which would not interoperate with a
spec-conformant client/server.

Change `kPrimePlcMacNetStatsClassId` from 83 to 85, refresh
the unit-test class_id check, the COSEM IC support matrix
and the COSEM API guide.

Tests: dlms_cosem_tests 277/277, full ctest 938/938.

BREAKING CHANGE: `CosemPrimePlcMacNetworkStatisticsObject`
instances now report class_id `85` instead of `83` in their
descriptor and on the wire. Clients/servers that previously
interoperated with the incorrect class_id `83` will need to
be updated to the spec-conformant id `85`.
