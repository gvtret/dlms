fix(cosem)!: gate Association LN user_list/current_user on class version 3

The Association LN IC `15` built-in object exposed the `user_list`
(attribute `10`), `current_user` (attribute `11`), `add_user`
(method `5`) and `remove_user` (method `6`) elements on class version
`2` instances. IEC 62056-6-2 ED4 (2021) clause 4.4.4 and DLMS UA Blue
Book Ed. 12.1 clause 4.4.4 define those elements for class version `3`
only; version `2` retains the v1 surface (attributes `1`-`9`, methods
`1`-`4`).

Construction of a v2 instance now clears caller-supplied
`users`/`currentUser` payloads, reports `NoAccess` for attributes
`10`-`11` and methods `5`-`6`, returns `AttributeNotFound` for reads
of `10` or `11`, and returns `MethodNotFound` for invocations of `5`
or `6`. The v0, v1 and v3 surfaces and the access-rights/object-list
encoders are unchanged. `MaxSupportedVersion` stays at `3`.

Added regression test
`CosemAssociationLnObject.Version2DoesNotExposeUserAttributesOrMethods`
that locks the v2 surface. Verified with the full COSEM gtest binary
(270/270) and `ctest --test-dir build-mingw64 --output-on-failure`
(931/931).

Marked as breaking: callers that constructed a v2 instance with a
non-empty `users` vector now observe an empty `Users()` collection
and a default-initialised `CurrentUser()`; reads of attribute `10`/`11`
and invocations of method `5`/`6` against v2 instances now report
`AttributeNotFound`/`MethodNotFound` instead of returning a value or
`UnsupportedFeature`.
