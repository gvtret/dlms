feat: align builtin push setup with iec 62056-6-2 ed4 v2 surface

Phase 287. Before this commit CosemPushSetupObject reported
MaxSupportedVersion = 1 but exposed all 13 attributes (1..13) and gated
the second half (8..13) only on `version >= 1u`. That is a hybrid that
matches neither v1 nor v2 in IEC 62056-6-2 ED4 (2021) / DLMS UA Blue
Book Ed. 16 IC 40:

  v0  attrs 1..7,  method 1 push (m)
  v1  attrs 1..10 (adds port_reference, push_client_SAP,
                   push_protection_parameters), method 1 push (m)
  v2  attrs 1..13 (adds push_operation_method,
                   confirmation_parameters,
                   last_confirmation_date_time),
                   method 1 push (m), method 2 reset (o)

repetition_delay (attr 7) is long-unsigned in v0/v1 and a structure
{repetition_delay_min, repetition_delay_exponent, repetition_delay_max}
in v2. The buffer is opaque; the caller encodes the value that matches
the negotiated version.

This commit bumps MaxSupportedVersion to 2, splits the version gating
so that attrs 8..10 require v1+ and attrs 11..13 require v2+, and adds
method 2 reset for v2 only. On a v2 instance reset clears the stored
last_confirmation_date_time buffer (the only persistent state the
built-in object owns) and returns Ok; on v0/v1 instances reset returns
MethodNotFound, matching the optional-method-not-instantiated rule.

Two real bugs fixed:
- On v1 instances, attrs 11..13 used to be readable/writable as the
  caller-supplied buffers. Per ED4 they only exist in v2; reads and
  writes now report AttributeNotFound on v1 (and on v0, as before).
- Method 2 used to fall through to MethodNotFound on all versions; on
  v2 it now correctly returns Ok and clears
  last_confirmation_date_time.

surface.
