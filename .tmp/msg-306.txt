fix(cosem)!: correct PRIME PLC MAC functional params class_id 81->83

IEC 62056-6-2 ED4 (2021) §4.12.7 and DLMS UA Blue Book Ed.
12.1 §4.12.7 both define "PRIME NB OFDM PLC MAC functional
parameters" with class_id = 83, not 81. Class_id 81 is
reserved for the unrelated "PRIME NB OFDM PLC Physical
layer counters" IC.

Our built-in `CosemPrimePlcMacFunctionalParametersObject`
carried a legacy 8-attribute subset of the spec layout but
reported the wrong class_id on the wire, which would not
interoperate with a spec-conformant client/server.

Change `kPrimePlcMacFunctionalParamsClassId` from 81 to 83,
refresh the unit-test class_id check, the COSEM IC support
matrix and the COSEM API guide. The matrix now lists IC `81`
separately as application-provided.

The remaining spec attributes (`mac_node_hierarchy_level`,
`mac_beacon_slot_count`, `mac_beacon_rx_slot`,
`mac_beacon_tx_slot`, `mac_beacon_rx_frequency`,
`mac_beacon_tx_frequency`, plus the move of
`mac_capabilities` to id `14`) are queued for a follow-up
rebuild.

Tests: dlms_cosem_tests 277/277, full ctest 938/938.

BREAKING CHANGE: `CosemPrimePlcMacFunctionalParametersObject`
instances now report class_id `83` instead of `81` in their
descriptor and on the wire. Clients/servers that previously
interoperated with the incorrect class_id `81` will need to
be updated to the spec-conformant id `83`.
