fix(cosem)!: rebuild IC 25 M-Bus slave port setup to match spec

IEC 62056-6-2 ED4 (2021) §4.8.2 and DLMS UA Blue Book Ed. 12.1
§4.8.1 define IC 25 with five attributes (1 logical_name,
2 default_baud, 3 avail_baud, 4 addr_state, 5 bus_address) and an
empty "Specific methods | m/o" column. The built-in object
previously used non-spec attribute names `status`/`mbus_port_reference`
for attributes 4 and 5 (mismodelling them as a status enum and an
octet-string reference to another object), and surfaced a phantom
`reset` method (id 1) that no edition of the spec defines.

Rebuild the constructor + accessor signature around the four spec
content buffers (`default_baud`, `avail_baud`, `addr_state`,
`bus_address`). Drop the `kMBusSlavePortSetupResetMethodId`
constant; `InvokeMethod` now returns `MethodNotFound` for every id
and clears method output. Attributes 2..5 keep sharing the
caller-selected `AttributeAccessMode`; logical_name stays
read-only.

Replace the four `CosemMBusSlavePortSetupObject` regression tests
with versions covering the new attribute layout and rename the
method test `NoMethodsDefined`, asserting `MethodNotFound` for
every probed id.

Refresh the IC support matrix, COSEM API guide and COSEM test
plan to document the new attribute names, the removed `reset`
method and the zero-method `MethodNotFound` semantics.

Tests: dlms_cosem_tests 275/275, full ctest 936/936.

BREAKING CHANGE: `CosemMBusSlavePortSetupObject` constructors now
take `availBaud`/`addrState`/`busAddress` parameters instead of
`availableBaud`/`status`/`mbusPortReference`, and the
`AvailableBaud()`/`Status()`/`MBusPortReference()` accessors are
renamed `AvailBaud()`/`AddrState()`/`BusAddress()`. Callers that
previously dispatched method id `1` against this IC now receive
`MethodNotFound` instead of `UnsupportedFeature`.
